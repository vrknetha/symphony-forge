# Forge v1.2.43

## What changes for client repos

- When close pushes only its review records on top of code that CI already tests, it waits for that run and does not start a new one (issue 1656). At one client, these record pushes caused about 70% of all CI runs. Nothing to do.
- When GitHub cancels a CI run, close starts it again once, or waits for the newer run of the same workflow. It counts the run as failed only when the second attempt fails too (issue 1661). Nothing to do.
- When CI fails only in some test groups, close and merge rerun only those jobs once and wait for them, as land already did. A single tests job that runs out of time still gets the advice "rerun the tests job, or split the suite" (issue 1664). Follow that advice when you see it.
- When GitHub's rate limit stops close, merge or land, they wait until GitHub's reset time and then continue. The board and `forge next` do not wait (issue 1665). Do not rerun them while they wait.
- When `forge.toml` sets `test_runner`, the scheduled full-suite job runs there. The test job on those runners can no longer write check results; a separate result job posts them (issue 1660). The upgrade's sync rewrites the workflow.
- `forge land <item> <item>` tests the named ready items together once and merges them in order, and leaves every other item alone. If you run it again after one item merged, it skips that item and lands the rest. Use it for chosen items.
- In a repo with several test groups, a pull request that changes 5 or fewer code files, and no lockfile, shared settings, CI workflow or Forge test-selection script, runs one test group instead of all of them. A repo whose test command has a fixed number of groups keeps running all of them. Nothing to do.
- When both Claude Code and Codex are installed, `forge init` sets `workers = "claude"` in a new repo: Claude builds, and Codex does the code reviews and cold reads. Existing repos keep their setting. To change an existing repo, ask the owner first.

## Known issues

- **Land leaves a teammate's ready item out of the combined test run.** When two people close items on different laptops, land merges the teammate's item alone. A clone that has not fetched a merge done elsewhere can also refuse an item as not started (issue 1674). Workaround: close both items on the same laptop first, and run `git fetch` before a named `forge land`.
- **Land can refuse every member when the main checkout pins an older release.** It runs the combined check and then refuses each item (issue 1675). Workaround: update the main checkout to the default branch before you run land.
- **A cancelled check from a service outside GitHub Actions counts as failed.** Forge has nothing to rerun for it. Workaround: none known; tell the owner.
