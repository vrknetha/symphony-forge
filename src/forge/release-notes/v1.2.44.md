# Forge v1.2.44

## What changes for client repos

- Close, merge and land poll CI every 60 seconds instead of every 15. `FORGE_CHECKS_POLL` sets another interval in seconds. Nothing to do.
- Check waits are limited by the GitHub API requests left this hour, so parallel closes no longer use up the account's quota. Nothing to do.
- Close and merge keep waiting while checks are queued or running, with a progress line, instead of stopping after 90 minutes (issue 1666). Only the time a job runs counts against the test time limit, not the time it waits for a runner (issue 1639). A failed required check still ends the wait at once. Do not interrupt a wait that shows progress.
- After the checks finish, close prints one CI time line: wall time against the 10-minute budget, runner minutes, the slowest job, and queue, setup, selection and test time. `forge doctor` warns when recent merged pull requests usually take over 10 minutes. Act on that warning with the owner.
- A docs-only pull request no longer uses a fast test runner. Nothing to do.
- Fixes get two review rounds before they ask the owner, like story parts. At the limit, ask the owner what to do with the open findings.
- `forge next` lists each pending owner choice first, with how long it has waited. When a fix is predicted to need more than five code files, Forge asks for the size allowance at fix start. Answer the owner choices before other work.
- When two or more items are ready, `forge next` suggests one `forge land <item> <item>` command for all of them. Run that command.
- In a repo whose tests run in CI, each merge to main runs the tests related to that merge, and Forge merges nothing while main's newest test result is red. (v1.2.45 replaces this with a gate on the nightly run.)
- Merge prints "Merged <item>: started <time>, merged <time>, <h>h<m>m start to merge; biggest wait: <cause>", and the board shows the median start-to-merge time of the day. Hold, decision, wait and resume times are recorded, so the time splits exactly. Nothing to do.
- In a repo with several test groups, a change of 5 or fewer code files runs one test group. Nothing to do.
- `forge task start` bases a task only on its own story branch plus main. Before, it could carry another story's open task commits. Nothing to do.
- `forge next` no longer crashes after `forge fix drop` removes a fix's checkout. Nothing to do.
- The generated `.claude` and `.codex` copies of the Forge guide come from one template. Nothing to do.
- The testing rules and the guide now say: browser tests run nightly; test selection follows the real import graph; check the test tool's own file isolation before splitting runtimes; await outstanding async work before a shared reset; use one CI test worker per core; and what to do when CI is over 10 minutes. Follow them when you write or fix tests.
- `forge machine --box setup --host <host>` sets up a machine you own for Codex build rounds, and `--box off` turns it off. Ask the owner before you set up a machine.
- The first close after the upgrade repairs at most the open items and the 20 most recently merged ones, and does this once. Nothing to do.

## Known issues

- **After `forge fix amend`, close reviews against the original Done-when.** Close can block a fix with a "Not done" finding that quotes the old Done-when (issue 1699). Workaround: close reads the amended Done-when, but an earlier finding that quotes the old Done-when can still block. When the owner agreed the change, dismiss it with `forge close <fix> --dismiss <n> --because "<why>"`.
- **No command retires a started story part.** A replacement part stacks on the old one (issue 1712). Workaround: tag the old head (`archive/<KEY>-<TASK>`), close its pull request, then remove the task worktree (`git worktree remove <path>`) and delete the task branch locally and on origin; `forge next` then starts the replacement from main.
- **A stacked part can loop on a replay conflict while main keeps moving.** Close replays the part again and again. Workaround: none known; tell the owner.
- **Forge's own record pushes cancel the pull request's running tests.** A push during close cancels the running test groups (issue 1723). Workaround: none in the repo; run `forge close <item>` again after the cancelled run, and wait for the newer run.
- **A small fix that merged main runs every test group.** The fix is judged by the merge's changes, not its own. Workaround: none; wait for all groups.
