# Forge v1.2.45

## What changes for client repos

- Forge's own record commits during close (review results, owner choices) wait until the pull request's checks report. They no longer cancel running tests and restart every group on unchanged code (issue 1723). Nothing to do.
- A change runs one test group only when its selected tests are under a quarter of all tests, so a small change to a central file runs all configured groups instead of hitting the time limit in one group. When Forge cannot judge the selection, for example with a custom test command, it runs all groups. Nothing to do.
- A change that merged main is judged by the pull request's own changes. Test files that main's merges added or changed still run. Nothing to do.
- When two or more items are Ready, close names one `forge land <a> <b>` command, which tests them together in one CI run. One Ready item still says `forge merge`. Run the command it names.
- No test run starts on main after each merge. The newest nightly full run gates merges. Fixes always merge, so the repair path is never blocked. Only story parts wait while the nightly run is red, and the refusal names that run. If it is red, start a fix that repairs it and merge that fix. A scheduled full run tests the commit it started for, so a merge during the nightly run no longer turns main red without a failing test.
- Related-test selection follows test helpers imported by their short name. Nothing to do.
- `forge upgrade` counts a run as in progress only while its process is alive. Runs whose process is gone no longer block the upgrade. Nothing to do.
- The review lists deleted, minified, source-map and generated files by path and size, without their content, so a fix that deletes a large build folder can be reviewed (issue 1728). Nothing to do.
- A stacked part whose one-by-one replay conflicts after its parent merged is replayed as one squash. Earlier review rounds stay valid on other machines. Nothing to do.
- The client guide again says to start the full run right after the last product merge for a release or sign-off. Do that before a release or sign-off.
- On Windows, `forge merge` started inside the item's worktree no longer reports an error after a successful merge when it cannot remove that folder. Nothing to do.

## Known issues

- **Two record branches with the same code can reuse the older test result.** When two record branches with the same code are merged, a record-only run can reuse the older of their test results. Workaround: none known; tell the owner.
- **A hand rerun of the original test run may not be seen after many record pushes.** After more than about 15 record pushes on one pull request, a record-only run may not see a hand rerun of the original run. Workaround: none known; tell the owner.
- **A review finding that cites a path inside Forge's temporary review tree is rejected.** Close stops on it. Workaround: run `forge close <item>` again.

## Fixed known issues

- **A stacked part can loop on a replay conflict while main keeps moving.**
- **Forge's own record pushes cancel the pull request's running tests.**
- **A small fix that merged main runs every test group.**
