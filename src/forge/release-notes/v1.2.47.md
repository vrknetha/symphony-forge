# Forge v1.2.47

## What changes for client repos

- Each Forge release now ships its notes inside Forge. After an upgrade, the upgrade output lists the changes of every release between the old and the new version, then the open known issues. The first `forge next` on each computer shows the same list once to the agent. The agent tells the owner what changed and works the new way.
- `forge sync` writes a "Known Forge issues" part at the end of the Forge guide, with each open issue and its workaround. A fixed issue leaves the list after the upgrade to the release that fixes it. Nothing to do.
- Each Done-when line names the test that proves it, in the Proof list of the builder's last commit. Close checks that a named pytest test is on the branch, ran, passed and was not skipped. For a Vitest or Playwright test, close checks only that the test is on the branch. A line that changes only settings, docs or tests can name a check. Before a builder adds a test, it names the closest existing test and reuses or extends it where it can. An item that is open during the upgrade writes its Proof list in the new form at its next close.
- For a fix, close and CI also run the fix's new or changed pytest Done-when test on the code before the fix, in a temporary copy. The test must fail there. Name only the test cases that fail on the old code as Done-when tests, and put the others on `- check:` lines. When the test cannot start on the old code, close gives a warning and the review judges the test.
- When a native Claude builder puts its Proof list in the handback report but not in a commit, `forge handback` writes the list into an empty commit, so close finds it. The worker brief states the exact place and form of the list.
- Close no longer waits silently for GitHub API quota. While it waits, it prints the REST and GraphQL numbers every 2 minutes, and it stops waiting as soon as the quota is fine. Nothing to do.
- A task or fix branch takes `tools`, `workers` and `models` from the default branch's `forge.toml`, except a setting that the branch itself changed. A branch started before a settings change no longer runs on the old workers or models. Nothing to do.
- `forge start` and `forge next` print a waiting intake prompt again, with its handback command, when the first print was lost. Nothing to do.
- A refused `forge close --resolve` on a review loop that has not stopped says what state is needed and gives the real next command.
- When a story's design part redraws the screens and only the plan's Design line changes, the story keeps its approval and its cold read. Any other change to the plan still needs a new approval.
- Forge ships a playwright-tests skill to every repo: the e2e folder layout, fixtures, sign-in by saved state, locators, workers from the environment, one base seed per worker with all other setup through the app's real APIs, CI sharding with one merged report, desktop browser tests on pull requests and all browsers nightly, and zero retries in CI. Builders and reviewers follow it.
- Codex runs on SDK 0.171.0 and Claude on Claude Agent SDK 0.2.187. Forge's default Codex model becomes gpt-6.2-sol; reviews stay on gpt-6.1-terra. Existing repos keep their own model settings, and the upgrade says the new default. gpt-6.2-sol needs this release or newer, because older SDKs reject it on ChatGPT accounts.
- `forge upgrade` ends any close that is only waiting for CI, says which ones it ended, and then installs. The next `forge close` picks the wait up again; CI keeps running on GitHub.
- When `forge upgrade` is blocked by runs in progress, it lists each one with its id, kind and item and the exact `forge stop --id <id>` command for the person. A handback that Forge refuses as stopped or replaced also ends that round's lane entry (#1761).
- The Forge guide and worker brief now state items missed since v1.2.40: the workarounds for #1674, #1675, #1699 and #1712, what `forge land --all` counts as Merged, how answered worker questions clear and their limits, and the Vitest name-filter limit for one-group JS changes.
- Ending a close, by `forge stop`, by `forge upgrade` or by ending its process, also ends its whole process tree, including its review, so no review run stays alive. On Windows, `forge upgrade` waits for the launcher above a close to exit before it installs.
- `forge ask "<question>" [--model <model>]` asks Codex one read-only question on the same path builders use. It waits for a place in the agent lane, prints the answer and records the run. Set a default model under `[models.ask]`.

## Known issues

- **A teammate's first Codex turn asks for doctor.** A teammate who pulls the upgrade gets "run forge doctor --fix" at the first Codex turn. Workaround: run `forge doctor --fix`, which installs the new SDKs.
- **The new-default notice misses a clone's own model file.** The gpt-6.2-sol notice does not see a clone's own forge.local.toml that replaces the shared model settings. Workaround: check forge.local.toml by hand after the upgrade.
- **Sync overwrites a repo's own playwright-tests skill.** `forge sync` overwrites a repo's own file at .claude/skills/playwright-tests or .codex/skills/playwright-tests, as it does for the database and agents skills. Workaround: keep repo rules for browser tests in AGENTS.md, outside the forge block.
- **A Windows upgrade can fail beside a close that waits for CI.** On Windows, a close that waits for CI before it saves its review records is not seen as waiting, so the install can fail. Workaround: run `forge upgrade` again.
- **The printed stop command cannot end a very old run.** A run started by a very old Forge release records its process in an old form, so the printed `forge stop --id` cannot end it. Workaround: end that process by hand, then run `forge upgrade` again.
- **A Claude worker can wait behind its own forge ask.** A Claude worker that runs `forge ask` inside its own round can wait behind its own agent place. Workaround: ask from the coordinator between rounds.
- **A design redraw's kept approval is not yet proven through a second close.** If it does not hold, Forge asks for a new read and approval as before. Workaround: none; expect a new approval in that case.
- **A refused resolve after failed CI can name close.** After CI fails, a refused `forge close --resolve` can name `forge close` instead of `forge work`. Workaround: run it; close then names `forge work`.
- **A close can stay silent for a few minutes before its first quota line.** When GitHub's quota endpoint is slow and several closes wait at once, a close can print nothing for a few minutes before its first quota wait line. Workaround: none; let it wait.
- **A branch that changed one model entry keeps all its own model entries.** A task branch that changed one model entry keeps all its own model entries, not only the changed one. Workaround: merge main into the branch to pick up main's other model changes.
- **Codex helper roles keep their role file's model.** On Codex, helper roles keep the model written in their role file when only a clone's forge.local.toml sets a different helper model. Workaround: set the helper model in forge.toml.
- **A fix that grows past five files during a round gets stuck.** The commit is refused for size, `forge fix allow-large` is refused while the round is open, and handback refuses uncommitted work (#1662, #1769). Workaround: `git stash`, hand back the round, run `forge fix allow-large "<reason>"` inside the fix folder with only the reason, `git stash pop`, commit. Ask for the allowance before a round that is likely to pass five files.
- **Upgrade drops hand edits in generated files.** The release's `forge sync` writes the CI workflow and other generated files again from forge.toml, so a hand edit there, such as a self-hosted runner or extra install steps, is lost (#1781). Workaround: before the upgrade, move each such edit into its forge.toml setting (runner, test, groups), then upgrade.
