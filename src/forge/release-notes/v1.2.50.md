# Forge v1.2.50

## What changes for client repos

- The coordinator now sees how full its chat is. When a Claude or Codex coordinator chat uses more than half of its context window, a hook adds one line with the token count and the window size. At the next quiet moment (after a merge or while checks run), the coordinator runs `forge hook handoff`, adds its open decisions, lessons and background-job log paths to `.git/forge/handoff.md`, and asks the owner to clear the chat. The guide's earlier rule "hand over at 20 to 30%, never past 40%" is replaced by "more than half, at a quiet moment".
- A new or cleared chat in a Forge repo starts with one line that names the handoff note and its date and says to read it first, then run `forge next`. Builder sessions do not get this line.
- When a repo's test setting runs one combined script and it has no quick-test setting, `forge doctor`, the upgrade and adoption say so in one line; Forge writes no setting. The guide tells the agent how to write, check and propose a quicker command through a small fix.
- On Windows, a builder's own test run skips each separate step of its test command that runs only Playwright or Cypress browser tests. The pull request check, the final check and the full test run still run them.
- When the latest full test run on the main branch fails, the board shows it under Needs you with a link to the run, and `forge next` marks it Needs you. It stays until a later full run passes.
- An Antigravity review that ends after a refused tool request no longer stops with "review engine returned empty output". It returns Neon's written review, or stops with a message that names the refused step.

## Known issues

- **The half-window line can be missed on older Claude models.** A coordinator on an older Claude model with a 200K window (for example Opus 4.1) is measured against a 1M window, so it gets no line before the chat is shortened automatically. Workaround: use a current Claude model, or hand over by hand when the chat feels long.
