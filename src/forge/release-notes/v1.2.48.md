# Forge v1.2.48

## What changes for client repos

- The app baseline that builders read before screen work now lists the owner's design rules. Never: gradients or glow, icons in rounded boxes, all caps or eyebrow labels, nested cards or decorative pills, bold text (regular and medium weights only). Always: sentence case, semantic tokens and never a hex value outside the theme's own values, shadows only on things that float, motion under 300 ms with no bounce, and a check at 390 px width, in dark mode and with the keyboard.
- Close refuses a changed app screen file that uses bold text, all-caps styling, a background gradient, a hex colour outside a theme value, or motion of 300 ms or more. Only changed screen files are checked, so an existing app is not blocked on upgrade. To keep a case, put `forge-ui-ignore <rule>: <reason>` in the file. The waiver covers that rule for the whole file, so keep other uses of the rule out of that file.
- `forge story drop` can now set aside an approved story whose parts are started but not merged. It keeps the story's branches, closes its open pull requests without merging them, and frees its parts' files for other stories. A dropped story's parts cannot start, close or land again. The refusal stays when a part has already merged (#1789).
- Close no longer waits for GitHub quota when many closes run at once and GitHub still has budget left. Before, more than eight closes on one machine printed "Waiting for GitHub API quota" for no reason. Nothing to do.
- `forge merge` no longer crashes when the task's worktree is removed while it waits for checks, for example by a second merge. It finishes the wait and prints its Merged line (#1794). Nothing to do.

## Known issues

- **A handback with the wrong round number says the round was stopped.** `forge handback` gives the same message for a wrong round number as for a stopped round, and no next step (#1791). Workaround: hand back with the round number from the last `forge work` output, or run `forge next`, which names the pending handback; run the handback again with that round.
- **The design checks read text, not the rendered page.** A word such as `uppercase` in a class name, a long spinner animation, or a `#abc` value that is not a colour can be reported. `<strong>` and `<b>` tags and motion times set in seconds by animation libraries are not checked. Workaround: put `forge-ui-ignore <rule>: <reason>` in the file; it covers that rule for the whole file, and the review still reads the rest.
