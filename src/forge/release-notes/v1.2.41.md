# Forge v1.2.41

## What changes for client repos

- pnpm repos: the generated CI workflow sets up pnpm before the tests (issue 1614), also when the only pnpm lockfile is in a subfolder. The upgrade's sync rewrites the workflow; commit it with the upgrade.
- The review check no longer runs before close posts its updated review (issue 1594). Nothing to do.
- A short network outage during a queued merge is retried instead of stopping the merge (issue 1598). Nothing to do.
- The roadmap refusal says why the entry is needed and where it goes (issue 1603). Follow the refusal's step.
- `forge close <item> --show` prints the full text of the last close's findings again, without running close. Use it to read findings in full.
- A fix that changes a forge.toml test setting keeps that change when main moves (issue 1599). A fix whose only change is a carried idea is built before it can merge: run `forge work <fix>` first.
- When GitHub fails to start the review check, close says so at once and gives the step that starts it again. Follow that step.
- The commit hook's generated-file check is faster again. Nothing to do.

## Known issues

- **A hand-set size allowance on a prototype fix can keep a light review.** The light review can stay after a later sign-off. Workaround: none known; tell the owner.
- **A subfolder pnpm project can get the wrong pnpm version.** It happens in some setups. Workaround: set `engines.pnpm` in that project's package.json to the pnpm version its lockfile needs, then run `forge sync`.
- **A native worker can skip the build on retry after it runs out of quota.** It happens when the worker runs out of model quota right after its first commit on an ideas-only branch. Workaround: none known; tell the owner.
