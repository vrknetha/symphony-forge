# Forge v1.2.49

## What changes for client repos

- Forge now installs and upgrades from PyPI as `symphony-forge==<version>`. Every install line, upgrade, hook fallback, pinned-release run and generated CI workflow uses it, and no command names the old GitHub repository. Bug links and the plugin marketplace point at vrknetha/symphony-forge. A repo on v1.2.48 whose CI still installs from the old GitHub address: install the new version with `uv tool install --force symphony-forge==1.2.49`, then run `forge upgrade`.
- Google Antigravity (Gemini 4 Neon) can be the third coding agent. Set `workers = "antigravity"` in `forge.toml` for builds and fixes, or use it for cold reads and code reviews. Install Antigravity CLI 1.5.12 or newer and run `agy` to sign in. Forge's skills ship for Antigravity too.
- Builder briefs send fewer input tokens. The first brief names the standards file, the design notes for work that is not a screen, and the release history as files to open instead of pasting them. A repair round lists the changed files instead of the full change, and a long related-test list goes to a file with its count in the brief. Nothing to do.
- The coordinator guide says to hand over to a fresh chat at a quiet moment before the chat gets long, to delete session timers before `/clear`, and to use no repeating flow-check timers. `forge next` warns, with the other session named, when another coordinator session already runs on the same repo. Keep one coordinator chat per repo.
- The coordinator guide says to set a model on every subagent it starts itself: Sonnet for analysis and research, Haiku for sorting and search.
- The debugger, security and performance agents and the grill and Claude plan-read defaults use Sonnet 5.5 at high effort instead of Opus. Repos with their own model entries keep them.
- Finished work folders are removed by `forge doctor`, `next`, `start` and `land`, also when the pull request merged on another machine or on GitHub. Folders with uncommitted files or unpushed commits are never removed; they are listed with one next step.
- A failed proof check now says that test names must be in backticks and that a Proof list on a merge commit is not read.
- When the only failed required check is the review check, close starts that review job again once and waits for it. Before, a review check that failed before a CI fix stayed failed until someone started it again by hand.
- `forge.toml` can set `auto_more_round = true`: at the review limit, close gives one more review round by itself when every open blocking finding is a P0 or P1 functional finding, at most once per item, and says so. Every other choice still waits for the owner. Off by default.
- When the latest full test run on the main branch fails (Forge's nightly run, or the workflow the repo names for its full run), the board shows it under Needs you with a link to the run, and `forge next` marks it Needs you. It stays until a later full run passes. Other scheduled jobs never show there.

## Known issues

- **The recovery install can break a running Forge run.** The recovery step reinstalls Forge with `uv tool install --force`; a build, review or CI wait running on that machine at the same time can fail or mix releases. Workaround: let running Forge work finish, or stop it, before the recovery install.
- **A work branch started on v1.2.48 can still use the old GitHub address.** After the default branch upgrades, an existing work branch that pins v1.2.48 can try the disabled GitHub source when close merges the default branch. Workaround: merge the default branch into that work branch with v1.2.49 installed, or start the item again.
