# Forge v1.2.40

## What changes for client repos

- A story part that was started on an earlier part that was not merged yet now closes after that earlier part merges. Close leaves out the work the part took from the earlier part by a merge and replays only the part's own work, so it no longer stops with a conflict in the part's record file. The replay no longer depends on the developer's own git rebase settings. With uncommitted edits close still refuses and changes nothing. Nothing to do: after the earlier part merges, run `forge close <part>`.
- When several closes fetch the default branch at the same moment and git refuses one with a lock, Forge starts that change again up to twice (before: once). Nothing to do.
- The board keeps the whole title of a fix, so fix cards and the Merged list no longer end with three dots. Nothing to do.
- After /clear, or in a new session, the /forge pane shows no rows from before. If the first read fails it says only "Forge did not answer." A decision read by its short name shows its heading. A plain test run with no item has output to open, and output over 4 MB shows one line with the file's path. Nothing to do.

## Known issues

- **The /forge pane is not checked in the Claude desktop app.** It was checked by hand in a real terminal only, so the desktop look can be wrong. Workaround: none known; tell the owner.
- **Close recognises only work that a part took from its earlier part by a merge.** Work taken by a rebase can still stop close with a conflict; no work is lost. Workaround: none known; tell the owner.
- **A Forge program older than the pane can show a waiting run as running.** A run that waits for memory shows as running when Forge is older than the pane. Workaround: upgrade Forge to the release that has the pane.
