# Forge v1.2.46

## What changes for client repos

- CI test jobs and failed test files are rerun only after a runner loss, cancellation or timeout, not after a test fails its check. A test that passes only on a rerun is still reported as flaky. A failed test now needs a code fix, not a rerun.
- A pull request that changes only JavaScript or TypeScript test files runs one CI test group with the repo's change test command, as a docs-only change does. Nothing to do.
- In a repo with a custom test command that runs pytest only, with no splitting of its own, a small change now runs one CI test group. Mixed Python and JavaScript commands, commands that split tests themselves and unknown runners still run all groups. Nothing to do.
- After a failed nightly full run, a green full run started by hand on main frees story merges. Before, they waited for the next scheduled run. The hold message says so. To free merges sooner, start the full run by hand.
- After the coordinator answers a worker's question with a note round, an allow-large record or a fix amend, close and next no longer stop on that question. Other open questions stay open.
- In a repair round, a finding that an earlier round dismissed stays dismissed while it points at the same file and lines and that code has not changed. When that code changes, the finding is reviewed again. Nothing to do.
- When Codex reports that the model is at capacity, forge work and close wait and try the same turn again a few times, and say in one line that they wait for capacity. Let them wait.
- Close keeps a review finding that cites a file through Forge's temporary review folder, also on macOS, so close no longer needs a retry. Nothing to do.
- Close's CI timing counts retry time only for a test job that failed and ran again. A cancelled or queued attempt, a rerun of the setup job, or a step named "retry" no longer shows as retry time (issue 1751). Nothing to do.

## Known issues

- **A changed test file can run none of its tests in the one CI group.** It happens when a repo's change test command filters tests by name with Vitest's long option or its config setting. Workaround: filter with `--testNamePattern`, which Forge detects, and set no name filter in the Vitest config.
- **Close skips the capacity wait after a long review.** When Codex reports that the model is at capacity only after a review wrote long output, close makes its normal next try without the wait. Workaround: none known; tell the owner.
- **A failure mark can miss the job log when a later test hangs.** When a test fails and a later test in the same job hangs until CI cancels the job, the failure mark can stay in Forge's memory and miss the job log. Forge then reruns the job, as it did for every failed job before. Workaround: none; expect one rerun.
- **One answer can clear two questions, or miss one.** When one paragraph holds two questions, recording an allowance also clears the other one. On another machine, a question over 300 characters may not clear when its command comes after the cut. Questions that ask for other commands, such as `forge decision accept`, stay open. Workaround: run `forge work <item> --note "<answer>"`; one round clears each of them.
