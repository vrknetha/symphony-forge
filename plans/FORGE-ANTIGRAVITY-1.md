# Google Antigravity as a third coding agent

2 parts · Risks: a new outside vendor (Google); a personal Google account may not be allowed for automated runs · New moving parts: the Antigravity program (`agy`) as a third agent; one new Forge module that talks to it; two small generated files in repos that use Antigravity

## What changes for you

In this plan, "Antigravity" is Google's coding agent program (`agy`), with the model Gemini 4 Neon. A "family" is one agent program: Claude Code, Codex or Antigravity.

- A repo can send its builds and fixes to Antigravity. The agent turns it on in a settings change, after you agree: `workers = "antigravity"` in `forge.toml`. Each kind of work (build, fix, review, cold read) gets its own Antigravity model and effort in `forge.toml`, under `[models.<kind>.antigravity]`, as Claude and Codex have today. Without an entry, Forge uses Gemini 4 Neon. (Source: your decisions of 22 Nov 2026)
- A repair round continues the same Antigravity conversation, as for Claude. After a failed round, Forge raises the effort, as it does for Claude and Codex. (Source: your request of 22 Nov 2026)
- A repo can send its code reviews and its cold reads to Antigravity with a new setting: `reviews = "antigravity"`. The same setting can also name `codex` or `claude`. When it is set, Forge refuses a review by the family that built the change, in one plain line. A repo without the setting keeps today's choice of reviewer. (Source: your decisions of 22 Nov 2026)
- Antigravity runs wait for a place in the same agent lanes as Claude and Codex runs, `forge stop` ends them, and the board and the run records name Antigravity with its model, effort and token use. (Source: your request of 22 Nov 2026)
- An Antigravity worker gets the same block on destructive commands as Claude and Codex workers, and it reads the skills that Forge ships. Forge writes two small files for this, only in a repo whose settings name Antigravity. (Source: your request of 22 Nov 2026)
- Forge talks to Antigravity through Google's official connection for other tools (the Agent Client Protocol, a standard way for a tool to talk to a coding agent). It needs Antigravity 1.5 or newer. Forge does not install Antigravity; you install it once. (Source: your decision of 22 Nov 2026)
- Any Google sign-in works, and a personal Google account is the default. You sign in once in Antigravity itself. Forge never reads or keeps a sign-in or a key. (Source: your decision of 22 Nov 2026)
- `forge doctor` says whether Antigravity is installed, signed in and at version 1.5 or newer. It also warns that Google's terms for outside tools are unclear, and names a Gemini API key and Vertex AI (Google's cloud AI service) as other ways to sign in. (Source: your decision of 22 Nov 2026)
- Setup of a new repo says when Antigravity is installed and ready, and writes no Antigravity setting. (Source: your request of 22 Nov 2026)
- An existing repo keeps its Claude and Codex settings and works as before after the upgrade. Nothing changes until a settings change names Antigravity. (Source: your request of 22 Nov 2026)
- Not in this story: Antigravity as the coordinating agent (Claude Code or Codex still coordinates), Antigravity build rounds on your own machine, reviews that include screenshots (the review tool supports those only on Codex), and Antigravity's usage limits on the board.

Design: none (no screen; the board and the pane already show each run's family and model).

## Why

Forge runs only Claude and Codex today. A team that wants Google's agent cannot use Forge's build, review and merge flow with it, and a team that wants a reviewer from a third company has none.

## Done when

1. **A repo whose settings send builds to Antigravity builds its tasks and fixes there; forge work names the model and effort, and the run is recorded as Antigravity with its token use.**
2. **A repair round on an Antigravity build continues the same Antigravity conversation, and after a failed round it uses a higher effort, as with Claude and Codex.**
3. **A repo can send its code reviews and cold reads to Antigravity, and Forge refuses, in one plain line, a review by the same family that built the change.**
4. **Antigravity runs wait for a place in the shared agent lanes, forge stop ends them, and they get Forge's block on destructive commands and the skills Forge ships.**
5. **Doctor says whether Antigravity is installed, signed in and at version 1.5 or newer, and warns that Google's terms for outside tools are unclear, naming a Gemini API key and Vertex AI as other ways to sign in.**
6. **Setup of a new repo says when Antigravity is ready to use, and a repo whose settings do not name Antigravity works as before, also after upgrade.**

## Risks

These steps are sensitive or cannot be undone:

- A new outside vendor: Google. Each Antigravity run sends the brief and the code it reads to Google, as Claude and Codex runs send them to their companies.
- Google's terms. A Google staff answer (2 Nov 2026) allows Google's official connection with a personal account "for single-user interactive development". Google's FAQ says that wrapping Antigravity inside other coding tools "is not supported under consumer plans". Forge runs Antigravity with nobody at the screen, so a personal account is in a grey area. Google says it acts on the Antigravity account, not the whole Google account. A Gemini API key or Vertex AI sign-in avoids the question. The default stays a personal account, by your decision; doctor shows the warning.
- An Antigravity worker runs with full access, as Claude and Codex workers do. It can read and change what your user can. Forge's block on destructive commands still runs first.

Accepted limits, in plain words:
- An Antigravity conversation lives on the machine where it ran. On another machine, the next round starts a new conversation with the whole brief, which uses more tokens.
- Each start of Antigravity unpacks about 1 GB into the temporary folder (a note in T3 Code, another tool that drives Antigravity). How much time and disk this costs per round is not measured.
- Forge does not update Antigravity. Antigravity updates itself.

### How Antigravity's ACP agent works (evidence)

T3 Code clone at `/private/tmp/claude-501/-Users-ravikiranvemula-Workdir-symphony-forge/c01a489d-c76f-41c1-8371-d6f0052b027c/scratchpad/ext/t3code`, commit `c198f73b` (22 Nov 2026), MIT licence (Copyright 2026 T3 Tools Inc.). Forge describes behaviour and copies no code. Google's pages read on 22 Nov 2026.

- **Start.** `agy acp` speaks newline-delimited JSON-RPC on stdin and stdout, protocol version 1, and names itself `Antigravity ACP Server` (https://antigravity.google/docs/cli/acp/). T3 starts `[agy, "acp", "--gemini-dir", <its own profile>, "--app-data-dir", "antigravity-acp"]` with `cwd` the project (`apps/server/src/provider/antigravityAuthSupport.ts:546-573`); Forge uses the user's default profile, so it passes neither. Flags on Google's page include `--dangerously-skip-permissions`, `--add-dir`, `--login`, `--log-file`, `--disable-telemetry`. `agy acp` arrived in 1.5.0 (CHANGELOG 1.5.0; https://github.com/google-antigravity/antigravity-cli/issues/31). T3 needs 1.5 and recommends 1.5.12 (`docs/user/providers-antigravity.md`).
- **initialize.** T3 checks `agentInfo.name == "Antigravity ACP Server"`, `agentInfo.version`, `protocolVersion` 1 or 2, `agentCapabilities.loadSession`, `agentCapabilities.sessionCapabilities.resume` and an `oauth-personal` auth method (`apps/server/src/provider/AntigravityInstallation.ts:788-801`). Auth methods: `oauth-personal`, `oauth-business`, `gemini-api-key`, `agent-platform` (`packages/contracts/src/settings.ts:867-872`; Google's acp page also lists `terminal-login`).
- **Sign-in.** A request with no sign-in fails with code -32000; the 1.5 CLI answers `authenticate` with -32603 "No browser is available here" when it has no sign-in and no display (`antigravityAuthSupport.ts:167-177`). T3 always calls `authenticate` with its own configured method in its own profile (`apps/server/src/provider/acp/AntigravityAcpSupport.ts:124-125`). Google documents no command-line sign-in status check.
- **Sessions.** `session/new {cwd, mcpServers: []}`; to continue, T3 uses `session/resume {sessionId, cwd, mcpServers}` because "loading history replays tool calls; resume avoids replay" (`packages/provider-acp/src/server/AcpSessionRuntime.ts:2425-2455`; `apps/server/src/orchestration-v2/Adapters/AntigravityAdapterV2.ts:236`). Resume works from a new process, but the session comes back on the account's default model, thinking level and mode (https://github.com/google-antigravity/antigravity-cli/issues/1460, open on 1.5.3); T3 also refuses to let "a cold resume" replace a saved choice (`AntigravityAcpSupport.ts:284`).
- **Model and effort.** The `session/new` and `session/resume` answers carry `configOptions`: a select with id `model`, and a select with `category: "thought_level"` (`AntigravityAcpSupport.ts:238-252`). Both are set with `session/set_config_option {sessionId, configId, value}` (`AcpSessionRuntime.ts:2974-2978`; `apps/server/src/textGeneration/AntigravityTextGeneration.ts:268-287`). Runtime 1.4 and later list family ids such as `gemini-3.8-flash` with a separate thinking option (`AntigravityAcpSupport.ts:246-266`). Gemini 4 Neon has `low`, `medium` (default), `high` and `xhigh`, and is not on Free and Plus plans (https://antigravity.google/docs/models).
- **Permissions.** Over ACP, `agy` rejects the `yolo` and `auto_edit` modes; T3 stays in `default` and answers each `session/request_permission` (`AntigravityAcpSupport.ts:169-184`). Options have kinds `allow_once`, `allow_always`, `reject_once` (`apps/server/src/provider/acp/AntigravityProtocol.ts:91-115`). A request whose `toolCall.toolCallId` starts with `interaction_` is a question to the user, not a tool (`AntigravityProtocol.ts:63-66`). Google's page documents `agy acp --dangerously-skip-permissions`, which since 1.5.3 still blocks Google's own command denylist (CHANGELOG 1.5.3). A subagent's command can skip the permission request (issue #1658, 1.5.12).
- **Updates and the end of a turn.** `session/update` notifications carry `agent_message_chunk` (text), `tool_call` and `tool_call_update` (`kind` such as `read`, `edit`, `execute`; an `execute` call has `rawInput.CommandLine`, `AntigravityAcpSupport.ts:199`), and `usage_update {used, size}` for the context window. The `session/prompt` answer has `stopReason` (`end_turn`, `max_tokens`, `max_turn_requests`, `refusal`, `cancelled`) and `usage {inputTokens, outputTokens, cachedReadTokens, cachedWriteTokens, thoughtTokens}`. For Antigravity 1.5 and later, `inputTokens` leaves out `cachedReadTokens` and `outputTokens` already includes `thoughtTokens` (`packages/provider-acp/src/server/adapter.ts:333-371` and `:672-674`; `AntigravityAdapterV2.ts:295-296`). The ACP spec still marks `PromptResponse.usage` as draft (https://agentclientprotocol.com/rfds/end-turn-token-usage).
- **Hooks.** `<workspace>/.agents/hooks.json` maps a hook name to events; `PreToolUse` entries have a `matcher` (a regex on the tool name, such as `run_command`) and `hooks: [{type: "command", command, timeout}]`. The hook reads JSON with `toolCall {name, args}` on stdin and prints `{"decision": "allow" | "deny" | ..., "reason": "..."}` on stdout (https://antigravity.google/docs/hooks). The command tool is `run_command` with `CommandLine` (https://antigravity.google/docs/cli/headless, the `step_update` example).
- **Rules and skills.** Antigravity reads `AGENTS.md` (https://antigravity.google/docs/rules) and workspace skills from `.agents/skills/` (legacy `.agent/skills/`) (https://antigravity.google/docs/skills). A workspace `.agents/skills.json` lists more skill folders with `{"entries": [{"path": ...}]}`, and since 1.5.2 an entry that points outside the workspace through an absolute path, `../` or a link is skipped (CHANGELOG 1.5.2; T3's reader at `apps/server/src/provider/Drivers/AntigravitySkills.ts:49-61, 368-392`). T3 also reads `.gemini/skills` (`docs/user/providers-antigravity.md`); Google's pages do not list it.
- **Updates of the program.** `agy` updates itself unless `AGY_CLI_DISABLE_AUTO_UPDATE=1` (T3 sets it for its own copy, `antigravityAuthSupport.ts:237`); `agy update` also exists (CHANGELOG).

### The test agent

`tests/stubs/agy`, a Python program (with a `.cmd` shim on Windows, as `install_claude` writes one), installed by `install_agy(repo)` in `tests/test_antigravity_build.py` (imported by the other new test files) and pointed at with `AGY_BIN`. It is written fresh, after the behaviour of T3's `apps/server/scripts/acp-mock-agent.ts`. `agy --version` prints `STUB_AGY_VERSION` (default `1.5.14`). `agy acp [flags]` logs its argv, process id and every message both ways to `agy-calls.jsonl` beside itself, and answers:
- `initialize` with `agentInfo {name: "Antigravity ACP Server", version}`, `loadSession: true`, `sessionCapabilities: {resume: {}}` and the auth methods;
- `session/new` with a new id saved to `agy-sessions.json` beside it, and `configOptions`: `model` with `gemini-4-neon` and `gemini-3.8-flash`, and a `thought_level` option with `low`, `medium`, `high`, `xhigh`;
- `session/resume` of a saved id (an unknown id, or any id with `STUB_AGY_FORGET`, is error -32002);
- `session/set_config_option` (an unlisted value is -32602);
- `session/prompt`: one `tool_call` (`execute`, `rawInput.CommandLine` `git status`), one `session/request_permission` for an `edit` and one for a `read` (it logs the answers), a text chunk that echoes the session id, model and effort, a commit of the folder with `STUB_AGY_COMMIT`, a file left uncommitted with `STUB_AGY_DIRTY`, then `{stopReason: "end_turn", usage: {inputTokens: 200, cachedReadTokens: 1000, outputTokens: 300, thoughtTokens: 120}}`.

`STUB_AGY_SIGNED_OUT` answers `session/new` and `session/resume` with -32000; `STUB_AGY_HOLD` never answers `session/prompt` and ends when stdin closes. Every answer carries a field Forge does not know, as the Codex stub's answers do.
