# Google Antigravity as a third coding agent

4 parts · Risks: a new outside vendor (Google) · New moving parts: the Antigravity program (`agy`) as a third agent; one new Forge module that talks to it, with Forge's own Antigravity review; Forge's entries in two small files in repos that use Antigravity

## What changes for you

In this plan, "Antigravity" is Google's coding agent program (`agy`). A "family" is one agent program: Claude Code, Codex or Antigravity.

- A repo can send its builds and fixes to Antigravity, with `workers = "antigravity"` in `forge.toml`. The agent makes this settings change only after you agree. Each kind of work gets its own Antigravity model and effort under `[models.<kind>.antigravity]`, as Claude and Codex have today. Without an entry, Forge uses the default model of your Google plan. Gemini 4 Neon needs a plan above Free and Plus. (Source: your decisions of 22 Nov 2026; the plan default is the planner's answer to the first cold read)
- A repair round continues the same Antigravity conversation. After a failed round, Forge raises the effort, as for Claude and Codex. (Source: your request of 22 Nov 2026)
- A repo can name the family that reviews its code and reads its plans, with `reviews = "codex"`, `"claude"` or `"antigravity"`. When it is set, Forge refuses a code review by the family that built the change, in one plain line. A repo without the setting keeps today's choice. (Source: your decisions 1 and 4 of 22 Nov 2026)
- Forge runs an Antigravity review itself, in a throwaway copy of the change. The reviewer can only read. Hooks, tool servers and settings files that the change carries do not run. Its findings reach close like Codex findings, with the same instructions and the same format. (Source: your decision of 22 Nov 2026, after the first cold read)
- Antigravity runs wait in the same agent lanes as Claude and Codex runs, `forge stop` ends them, and the run records name Antigravity with its model, effort and token use. (Source: your request of 22 Nov 2026)
- An Antigravity worker gets Forge's block on destructive commands and the skills Forge ships. Forge adds its entries to two small files, only in a repo whose `forge.toml` names Antigravity, and keeps what is already in them. A build does not start without the block. (Source: your request of 22 Nov 2026)
- Forge talks to Antigravity through Google's official connection for other tools (the Agent Client Protocol, a standard way for a tool to talk to a coding agent). It needs Antigravity 1.5.12 or newer, because earlier 1.5 releases could skip the block on Windows and leave background tasks running. You install Antigravity and sign in once, with your personal Google account by default; Forge never reads or keeps a sign-in or a key. (Source: your decisions of 22 Nov 2026; the 1.5.12 floor is the planner's answer to the first cold read)
- `forge doctor` says whether Antigravity is installed, signed in and new enough. (Source: your decision of 22 Nov 2026)
- Setup of a new repo says when a supported Antigravity is installed. An existing repo works as before after the upgrade, until a settings change names Antigravity. (Source: your request of 22 Nov 2026)
- Not in this story: the client sign-off review on Antigravity (it needs screenshots and split passes, which only the existing review tool has; it stays on Codex or Claude), Antigravity as the coordinating agent, Antigravity rounds on your own machine, and Antigravity token use or usage limits on the board and the pane.

Design: none (no screen).

## Why

Forge runs only Claude and Codex today. A team that wants Google's agent cannot use Forge's build, review and merge flow with it.

## Done when

1. **A repo whose settings send builds to Antigravity builds its tasks and fixes there; forge work names the model and effort, and the run is recorded as Antigravity with its token use.**
2. **A repair round on an Antigravity build continues the same Antigravity conversation, and after a failed round it uses a higher effort, as with Claude and Codex.**
3. **A repo can send its code reviews and cold reads to Antigravity, which reads only, runs nothing the reviewed change carries and returns findings to close like the other families, and Forge refuses, in one plain line, a code review by the family that built the change.**
4. **Antigravity runs wait for a place in the shared agent lanes, forge stop ends them, and they start only with Forge's block on destructive commands and with the skills Forge ships.**
5. **Doctor says whether Antigravity is installed, signed in and new enough.**
6. **Setup of a new repo says when a supported Antigravity is installed, and a repo whose settings do not name Antigravity works as before, also after upgrade.**

## Risks

These steps are sensitive or cannot be undone:

- A new outside vendor: Google. Each Antigravity run sends the brief and the code it reads to Google.
- Sign-in with a personal Google account. Evidence: a statement from Google that you shared on 22 Nov 2026, "You will NOT be banned ever for using Antigravity in T3Code." It names T3 Code, which runs the same official Antigravity connection that Forge uses. The default stays a personal account.
- An Antigravity worker runs with full access, as Claude and Codex workers do. Forge's block on destructive commands runs first.

Accepted limits:
- An Antigravity conversation lives on the machine where it ran; on another machine, the next round starts a new one with the whole brief.
- Each start of Antigravity unpacks about 1 GB into the temporary folder (a note in T3 Code, another tool that drives Antigravity). The cost per round is not measured.
- An Antigravity review reads a very large change in one pass, with the longest part of the change left for it to open itself; the existing review tool splits such a change into passes.
- Forge does not update Antigravity; Antigravity updates itself.

### The test agent

`tests/stubs/agy`, a Python program (with a `.cmd` shim on Windows), installed by `install_agy(repo)` in `tests/test_antigravity_build.py` and pointed at with `AGY_BIN`. Written fresh, after the behaviour of T3's `apps/server/scripts/acp-mock-agent.ts`. RUNTIME writes it; READS and REVIEW add the behaviours their tests name (test paths may be shared). `--version` prints `STUB_AGY_VERSION` (default `1.5.14`). `acp` logs argv, its process id, its `cwd` and every message to `agy-calls.jsonl` beside itself. Like Antigravity, it acts on the workspace: at start it runs the command of every server in `<cwd>/.agents/mcp_config.json`, and before its `execute` tool call it runs every `PreToolUse` hook in `<cwd>/.agents/hooks.json` with the Antigravity payload and obeys a deny decision.
