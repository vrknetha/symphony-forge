# Choose a builder for one item

2 parts · Risks: none one-way · New moving parts: none

## What changes for you

- You can pick who builds one task or fix: Claude, Codex or Antigravity (Gemini). Add `--tool claude`, `--tool codex` or `--tool antigravity` to `forge work <item>` or `forge land <item>`. The repo's other work keeps the builder that `forge.toml` names. (Source: the owner's request, 28 Nov 2026)
- To choose before the first round, add the same `--tool` to `forge fix start` or `forge task start`. The background runner starts approved work by itself, so a choice made at the start is already saved when its first round runs. (Source: the coordinator's follow-up, 28 Nov 2026)
- Forge remembers the choice for that item. Every later round on the item, including repair rounds and the rounds the background runner starts, uses the same builder until you pick another one. `forge next` and the "Building ..." line say that you chose it for this item. (Source: the owner's request, 28 Nov 2026)
- The model and effort come from the settings you already have for that builder, for example `[models.build.antigravity]` and `[models.fix.antigravity]` in `forge.toml` or `forge.local.toml`. There is no new setting. Without such an entry, Forge uses its built-in default for that builder. (Source: the owner's request, 28 Nov 2026)
- Forge refuses with one line, before it changes anything, when the builder is not installed or `tools` in `forge.toml` does not allow it. (Source: the owner's request, 28 Nov 2026)
- When a worker is stuck, `forge close <item> --resolve switch --tool antigravity --reason "<choice>"` moves the item to Antigravity in one step. Without `--tool`, a switch works as before (Claude to Codex, Codex to Claude, Antigravity to Claude). (Source: the owner's request, 28 Nov 2026)
- What each repo gets: a new repo has the option from its first command. An existing repo gets it when it upgrades to the release that has this story (v1.2.51). Nothing is migrated: an item with no saved choice builds as before. The coordinator guide that `forge sync` writes explains the option.

Design: none (no screen changes)

## Why

Forge builds every item with the builder that `forge.toml` names for the whole repo. A team that wants prompt and memory changes built on Antigravity while plain code stays on Codex has no supported way to do this. The only workaround is to write a short-lived `forge.local.toml` before each `forge work` and delete it after, which is easy to get wrong. Forge already keeps a per-item builder choice (the stuck-worker switch saves it) and already reads it in every round. This story adds direct ways to set it, early enough that the background runner honours it.

## Done when

1. **`forge work <item> --tool <claude|codex|antigravity>` and `forge land <item> --tool <family>` build with the named builder, save the choice for the item, and say the owner chose it for this item; later rounds, repair rounds and rounds the background runner starts keep it and use that builder's own model and effort from the existing `[models]` settings; `--tool` with several items or `--all` is refused.**
2. **`forge fix start --tool <family>` and `forge task start <part> --tool <family>` save the choice when the item starts, so its first round already uses it.**
3. **A builder that is not installed, or that `tools` does not allow, is refused in one line before anything changes, and the item's saved builder stays as it was.**
4. **`forge close <item> --resolve switch --tool <family>` moves a stuck item to that builder, Antigravity included; a switch without `--tool` keeps today's two-way mapping.**
5. **The coordinator guide, `docs/commands.md` and the command help describe `--tool` on all five commands.**

## Risks

Risks: none one-way. Each task reverts with its pull request.

Accepted limits:
- A fix has no gap: `forge fix start --tool` saves the choice before the runner sees the fix. A story part can still be started by the runner before you name a builder, and a part that waits for another cannot be started by hand early. The choice then applies from the next round on. To choose for the first round of a part, run `forge task start <part> --tool <family>` right after approval: if the runner already started it, the command refuses (already started) and `forge work <item> --tool <family>` is the fallback.
- Antigravity needs its program installed and signed in. When it is missing, the command refuses and says how to install it. Forge does not fall back to another builder.
- Changing builders in the middle of an item starts a fresh session for the new builder. This already happens today after a stuck-worker switch.
