# Short model names pick the newest model at each run

2 parts · Risks: none one-way; six accepted limits · New moving parts: none

## What changes for you

- `forge.toml` can name a model with a short name: `sol`, `astra`, `terra` or `luna` for Codex, and `sonnet`, `opus` or `haiku` for Claude. (Source: the owner's request, 18 Nov 2026)
- With a short name, each build, cold read and review uses the newest model of that name that the program running it offers. Forge checks this again when each round starts, not when Forge upgrades. When that program offers a newer model, the next round uses it, with no edit. (Source: the owner's request, 18 Nov 2026)
- Builds and cold reads that Forge starts itself run on Forge's own copy of Codex. That copy can offer fewer new models than the Codex app until a Forge release updates it. Today the newest Sol in Forge's copy is `gpt-6.1-sol`, and in the Codex app it is `gpt-6.2-sol`. Reviews, and rounds that a Codex session runs itself, use the Codex app's list. (Needed by: the short names above)
- A full model name, such as `gpt-6.1-terra`, stays exact: Forge uses that model and nothing else. (Source: the owner's request, 18 Nov 2026)
- Each round's line and its record name the exact model that ran, such as `gpt-6.2-sol`, not only the short name. (Source: the owner's request, 18 Nov 2026)
- If Codex offers no model of a short name, the round stops before it starts, with one line that lists the models Codex offers. (Source: the owner's request, 18 Nov 2026)
- What each repo gets. A new repo's `forge.toml` starts with short names, so it always gets the newest models. Reviews and cold reads on Codex stay on Terra at max effort: `terra` means `gpt-6.1-terra` today. An existing repo keeps its model names on upgrade; Forge changes nothing in its `forge.toml`. Its owner can change any name to a short name at any time. (Source: the owner's request, 18 Nov 2026)
- Cost. No model call is added. A Codex short name adds a local call to Codex's model list when each round starts: up to about one second for Forge's own copy of Codex, and about a tenth of a second for the Codex app. A newer model can cost more or less than the one it replaces. (Needed by: the short names above)

Design: none. The board and the pull request look the same; their model names are now the exact ones.

## Why

Forge's defaults and each client's `forge.toml` name fixed model versions, such as `gpt-6.1-sol`. When Codex or Claude adds a newer model, Forge needs a new release to change its defaults, and each client repo needs a hand edit. Until then, every repo keeps building on the older model. Today the Codex app already offers `gpt-6.2-sol`, and new repos still start on `gpt-6.1-sol`.

## Done when

1. **With a short name in `forge.toml`, each build, cold read and review uses the newest model of that name that the program running it offers, checked when each round starts, and a full name uses exactly that model.**
2. **Each round's line and record name the exact model that ran, and a Codex short name that Codex does not offer stops the round before it starts, with one line that lists the models Codex offers.**
3. **A new repo's `forge.toml` starts with short names, with reviews and cold reads on Terra at max effort, and an existing repo's model names do not change on upgrade.**

## Risks

Risks: none one-way. Each part reverts with its pull request. No saved record changes. No existing repo's `forge.toml` changes.

Accepted limits, in plain words:
- Claude decides what `sonnet`, `opus` and `haiku` mean. On some cloud providers they mean an earlier model. Forge does not check Claude's short names; Claude always accepts them.
- When a Claude session runs a round as its own subagent, Forge cannot see the model that the subagent used. That round's record keeps the short name. Rounds that Forge starts itself, and all reviews, name the exact model.
- When a Codex session runs a round as its own subagent, Forge checks the `codex` program on the machine. If the session runs on another Codex app with another model list, the round can name a model that app does not offer. Codex then stops that round with its own message.
- Files that Forge writes for Codex's own use cannot hold a short name, because Codex refuses short names. When `forge.toml` uses one, those files leave the model out. The round itself still names the exact model when it starts. Only the helpers that a Codex session's subagent starts on its own use that session's model.
- Before a round starts, the board shows the name from `forge.toml`. While a Claude review runs, the board shows the short name; the exact name shows when the review ends.
- Autoreview, the review helper, has its own retry: when the account cannot use `gpt-6-sol` or `gpt-5.6-sol`, it reviews on another model. If a repo names one of those two full names for reviews, such a review runs on the other model. The review's record names the model that ran.

### Options weighed

1. **Resolve at upgrade or sync and write the full name into `forge.toml`.** Rejected by the owner: the model must be the newest at each run, and `forge.toml` must not change on its own.
2. **Resolve inside the kit driver through the app-server's `model/list`** (already called at `codex_turn.py:221-232`). Rejected: reviews and session rounds never start the app-server, so they would need a second way, and the stop would come after the round took its place.
3. **Resolve inside `repo.models`.** Rejected: the board, `forge next` and `forge sync` call it too. They would call Codex, and a missing model would stop the board.
4. **One small function, called right before each place a Codex name reaches a tool, asking the program that runs the round, never cached (chosen).**
5. **Map Claude short names in Forge too.** Rejected: Claude Code already maps them, and the right model depends on the provider, which only Claude Code knows.

Score (F x H >= 2 x C): F 2 (a newer model comes every few weeks, and each needs a release plus an edit in every repo), H 2 (repos keep building on an older model: a slower or worse step), C 2 (about 120 product lines, no model call, no user step): 4 >= 4, kept.

### Decisions

- **New module `src/forge/model_names.py`** (about 45 lines): `CODEX = ("sol", "astra", "terra", "luna")`, `CLAUDE = ("sonnet", "opus", "haiku")`, `REFUSALS` with the stop above, and `exact(entry, kit)` as in item 1, with no cache. Merge its `REFUSALS` the way `close.py:75` merges `review_skip.REFUSALS`, if a refusal check needs it.
