# Keep builds running in AWS while the laptop sleeps

8 parts · Risks: three powerful sign-ins (GitHub, Claude, Codex) sit on a box while a round runs; the Claude token is a plan sign-in used from a cloud machine, and Anthropic's answer is not in yet; a box that dies before it writes the Codex sign-in back can leave an old one · New moving parts: per-developer sign-in secrets in your AWS account, a round machine role with short-lived credentials, a Codex sign-in lease in the AWS table, a bigger box size on trial, a round script on the box, round results in S3

## What changes for you

In this plan, a "box" is an AWS machine from the earlier stories (4 processors and 16 GiB of memory, aims to end within 3 hours). A "round" is one run of a builder (Claude, Codex or Neon) on one task or fix. "Story 1" is FORGE-PROVIDER-1 (the AWS setup, the machine limit and the lifetime rule). "Story 2" is FORGE-PROVIDER-2 (laptop test runs in boxes; a box works like a second laptop that Forge runs inside, with the laptop's lane rules). This story needs both.

- Build rounds can run in a box, so a round no longer stops when the laptop sleeps or shuts its lid. The laptop stays the one coordinator: it builds each round's brief, follows the round, runs every review and cold read, and decides the next step. Reviews and cold reads never go to a box. (Source: your decisions of 27 Nov 2026)
- It is off by default. A new client repo gets it off at setup. An existing client repo has it off after it upgrades and syncs, and its settings do not change. Both get the new steps in Forge's guide. To turn it on, the agent asks you, then a settings fix sets the new setting `box_rounds` in `forge.toml` to the families that may use a box, for example `["claude", "codex"]`. Forge reads it only from the default branch, never from the branch being built. It needs story 1's `aws_runners` and the box parts that story 2 adds to the AWS stack, but not story 2's `aws_tests`. (Source: your decision of 27 Nov 2026 that it is off by default; the setting name and the default-branch rule are the planner's choice; confirm)
- Box rounds work for public and private repos, so Forge's own public repo can use them. They need no GitHub App. They run only the developer's own item branch from the real commit of that item, checked from this repo's own GitHub repo and never from a fork, and never on GitHub Actions. Unsaved files never go: if the item's folder has unsaved files, the round stays on the laptop with one line that says so. (Source: your decision of 28 Nov 2026; the unsaved-files rule is the planner's choice)
- A round starts on the laptop first, while the laptop's load is under half of today's limit and its swap-out count is not growing over one second (story 2's rule); otherwise it goes to a box at once. (Source: your decision of 27 Nov 2026)
- Test boxes and round boxes are different machines. A test box (story 2) holds no sign-in. A round box holds only the sign-ins of one developer and one family, as short-lived credentials made when the round is placed; it never holds another developer's or another family's sign-in. Whoever can open a session or send commands to a round box can read its sign-ins, so the setup guide says to give that right to the developer only. (Source: Astra's certification of 28 Nov 2026; confirm)
- Claude rounds use every box from day one. Each developer makes their own one-year token with `claude setup-token` and saves it in their own AWS Secrets Manager. The box reads it when the round starts and wipes it when the round ends. The box runs Claude Code unchanged. Forge never sees the token: it prints the exact command and the developer runs it, and Forge only checks that a value is saved. You asked Anthropic about this use and chose to go on without an answer (28 Nov 2026); there is no gate. (Source: your decision of 27 Nov 2026)
- Codex gets one sign-in at a time. Codex's own page for automation (https://learn.chatgpt.com/docs/auth/ci-cd-auth) says to use one `auth.json` per runner or per serialized stream, and never to share the file across concurrent jobs or machines. So one Codex sign-in per developer is "leased" (lent to one box until that box is done with it), and the refreshed file is written back to the secret store after each run, before the lease ends. By default Codex rounds run one at a time on that sign-in. A second Codex round runs on the laptop, or waits as it does today. The developer makes this sign-in once, in a terminal on a box (it is a new sign-in, not a copy of the laptop's file). (Source: your decision of 27 Nov 2026; one stream by default is Astra's advice and the planner's choice; confirm)
- A trial comes next: one bigger box (8 processors, 32 GiB) that runs 3 to 4 Codex rounds through one Codex app server and one sign-in, counted as one machine in story 1's limit. The trial can record "no": if OpenAI's rules or the real test say no, the shared box is not built, the result goes in the release notes, and a Codex round that finds the sign-in leased runs in a box with an OpenAI API key, used only when you saved a key at setup (billed per use by OpenAI, outside the ChatGPT plan). (Source: your decision of 27 Nov 2026; the "can record no" rule is Astra's advice and the planner's choice; confirm)
- Neon is tried: the developer signs in once in a box terminal, Forge saves that sign-in like Codex's, and Forge then restores it on a fresh box and runs a small real check. Neon rounds use a box only if that check works. If it fails, Neon stays on the laptop with one line that says why. (Source: your decision of 27 Nov 2026)
- The box pushes the branch with the developer's own GitHub sign-in, read from their secret store. That is wider access than the Actions machines of story 1, which hold no GitHub sign-in. (Source: your decision of 27 Nov 2026; you chose the wider access knowingly)
- When the laptop is away, the round finishes in the box, pushes the item's branch, and saves its log and result in S3. When the laptop wakes, `forge work <item>` or the background runner reads the result, does not start a second round, and the item goes on to its review as after any round. The box keeps its own heartbeat while the round runs. The box aims to end within 3 hours; at 2 hours 45 minutes it stops the turn, pushes what is committed, and says time ran out, so the next round can go on. If the result is missing or gone, the round counts as lost and the next round starts from the branch as pushed. (Source: your decision of 27 Nov 2026; the 2 hours 45 minutes cut and the lost-result rule are the planner's choice; confirm)
- Watching, stopping, questions and notes work as for a laptop round. The round's log shows on the laptop while it runs. `forge stop` asks the box to stop, gives it up to 5 minutes to push committed work, then ends the box. A worker's question ends the round as now, and your answer (`forge work <item> --note "<answer>"`) starts a new round in a new box. Every box round starts a new conversation with the whole brief, so it uses more tokens than a continued one. (Source: your decision of 27 Nov 2026; the stop and log channel is the planner's choice; confirm)
- Turning AWS off deletes the saved sign-ins and the round results from AWS. It revokes nothing: the tokens stay valid at GitHub, Anthropic and OpenAI until revoked there, and `off` says so on its own line. (Source: Astra's certification of 28 Nov 2026)
- Cost, estimates only. A 4-processor box costs about $0.20 an hour; the 8-processor box about twice that; setup looks up the real price. A 40-minute round costs about $0.14 on a small box. Each saved sign-in costs about $0.40 a month in Secrets Manager per developer (up to 5, so about $2). Logs and results in S3 are deleted after 14 days and cost cents. Replacements, storage, traffic, function calls and OpenAI API use can add charges. The monthly amount in story 1 is still only an email, and its worst-case line uses the bigger box's price while that trial box is on.

## Why

Every build round runs on the laptop, so a round stops when the laptop sleeps, and a busy laptop makes rounds and tests wait: from 30 Sep to 27 Nov 2026 the evidence includes load of 370 and 211, swap use, and a round waiting about 45% of its time for a place. Story 1 moves CI and story 2 moves test runs. This story moves the rounds themselves, so the work goes on when the laptop is away. How much sooner work is ready is not measured yet.

3. **One Codex sign-in serves one box at a time for one developer: a second Codex round while it is leased runs on the laptop or waits; setup, refresh and the run all take the lease; the refreshed sign-in file is written back before the lease ends; the lease ends only when the box says it is done or AWS confirms the box is gone, and a sign-in that may have lost a refresh is refused until the developer signs in again.**
4. **A real trial of one bigger box (counted as one machine) records how many Codex rounds fit through one app server and whether OpenAI accepts it, and it can record no; by default Codex rounds run one at a time; only if the trial says yes, the box runs three Codex rounds at once through one app server and one sign-in; and when a busy-time round finds the sign-in leased and an OpenAI API key was saved at setup, it runs in a box with the key and never touches the sign-in file.**
5. **With the laptop gone after the round starts, the box finishes the round, pushes the item's branch with the developer's own GitHub sign-in, and saves the log and result in S3; when the laptop wakes, `forge work` and the background runner take that result before they prepare, merge or close anything and without starting a second round, and the item goes on to review as after a laptop round; a round that reaches 2 hours 45 minutes is stopped by the box, pushed and reported as out of time; a missing result counts as a lost round.**
6. **A Neon round goes to a box only after the one-time sign-in made in a box terminal is saved and has been restored on a fresh box and run for real, under the same one-box-at-a-time lease as Codex; otherwise it runs on the laptop with one line that says why.**

## Risks

These steps are sensitive or cannot be undone:

- While a round runs, the box holds its developer's GitHub sign-in and the sign-in of the round's family (Claude or Codex). The worker and the repo's test code run on the box with internet access and can read them. They are read once and wiped at the end, not hidden during the round. A bad instruction in the repo or in a web page the worker reads could send them out. The GitHub sign-in reaches every repo the developer can reach. You chose this knowingly; keep the box's AWS role and the secrets in an account that holds nothing else. Anyone with Session Manager or command rights on a round box can read them too.
- The Claude token is the developer's own plan sign-in, used from a cloud machine in automation. Anthropic's terms for this use are not confirmed. You asked Anthropic and chose to continue without waiting for the answer (28 Nov 2026). Anthropic can block the token at any time; a round then fails with the one line Claude Code prints, and the developer makes a new token. There is no gate in the build.
- A Codex round that ends because AWS stopped the box may never write the refreshed sign-in back. The saved copy is then marked old, and the next box round refuses until the developer signs in again.
- On a public repo, a round reads and runs only the developer's own item branch from its real commit; a fork's code and unsaved files never reach a box through this story.
- A round stopped by AWS before it pushes loses its uncommitted work, as turning off a laptop would not. The box pushes committed work at 2 hours 45 minutes, on `forge stop` and when the round ends.
- Codex and Neon sign-in files are made in a box terminal. Neon's way of saving a sign-in on Linux is not documented; it may not work at all, and the story then leaves Neon on the laptop.
- Turning AWS off deletes the saved sign-ins and the S3 results. It cannot be undone, and it does not revoke any token.
